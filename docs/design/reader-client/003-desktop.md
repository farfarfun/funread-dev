# 桌面端

funread 和 Legado 那一类竞品最大的区别是**它们做 APP，我们做 Web**，而且这个 Web
要同时服务手机和 PC。原生 APP 只需要为一种形态设计，我们不行。

## 宽度和输入方式是两件事

这是整章的前提。不能只看屏幕宽度就决定一切：

| 设备 | 宽度 | 输入 | 要什么 |
| --- | --- | --- | --- |
| 手机竖屏 | 窄 | 手指 | 底栏、44px 触控区、边缘手势 |
| 平板横屏 | 宽 | 手指 | 侧栏、**仍然要 44px 触控区**、边缘手势 |
| 桌面浏览器 | 宽 | 鼠标 | 侧栏、紧凑控件、键盘、hover |
| 窄窗口的桌面浏览器 | 窄 | 鼠标 | 底栏、紧凑控件、键盘、hover |

所以拆成两个独立判断，不是一个「是不是移动端」：

- **`isWide`**（`min-width: 900px`）—— 有没有横向空间。决定侧栏 vs 底栏、多列 vs 单列。
- **`isTouch`**（`pointer: coarse`）—— 主输入是不是手指。决定触控区尺寸、是否启用
  边缘手势、是否上 hover。

CSS 侧对应 `@media (min-width: 900px)` 与 `@media (pointer: coarse)`；JS 侧是
`useViewport()` 的 `isWide` / `isTouch`。**两边的断点必须一致**（900），否则会出现
JS 认为该用侧栏而 CSS 还在底栏布局，侧栏和底栏同时存在。

## 导航：底栏 ↔ 侧栏

窄屏底部 TabBar，宽屏左侧 SideRail，**互斥**。

底部导航是移动端惯例，因为那里是拇指能到的地方。桌面没有拇指，而一条横跨 2560px
的底栏既不合常规，也把四个目标推到彼此极远的位置。

两者共用 `components/web/navigation.ts` 的 `TABS` —— 各写一份迟早漂移（加了一个
tab 只改了一边）。

侧栏底部列出快捷键。桌面上键盘是主要交互方式，列出来比让人猜强。

## 键盘

`useShortcuts()` 统一挂载，两条硬规则写在它的 docstring 里：**输入框里不拦截**
（否则搜索框的左右方向键没法移动光标）、**带修饰键的组合不拦截**（`Ctrl+←` 是
浏览器的，抢它会打断已有的肌肉记忆）。

| 页面 | 键 | 动作 |
| --- | --- | --- |
| 正文 | <kbd>←</kbd> <kbd>→</kbd> | 上/下一章 |
| 正文 | <kbd>t</kbd> / <kbd>s</kbd> / <kbd>h</kbd> | 目录 / 设置 / 换源 |
| 正文 | <kbd>Esc</kbd> | 逐层关闭：抽屉 → 工具栏 → 回详情 |
| 文章 | <kbd>s</kbd> / <kbd>f</kbd> / <kbd>Esc</kbd> | 设置 / 收藏 / 返回列表 |
| 搜索 | <kbd>/</kbd> / <kbd>Esc</kbd> | 聚焦输入框 / 清空 |
| 书架 | <kbd>/</kbd> / <kbd>g</kbd> | 去搜索 / 切网格列表 |
| 文章列表 | <kbd>r</kbd> / <kbd>a</kbd> / <kbd>Esc</kbd> | 刷新 / 全部已读 / 返回 |

**空格与 PageDown 不拦截** —— 滚动式阅读里浏览器的默认滚动行为本来就是对的。

Esc 按「最内层先关」分层，一次 Esc 不会把人直接弹出正文。

## 正文页：边缘点击只在触屏启用

手机上左右各 25% 是翻章带。桌面上这**必须关掉**，两个理由：

1. 2560px 屏上那是 640px 的死区；
2. 鼠标用户会把点击理解成选中文字 —— 想复制一段话结果跳章了。

桌面改为常驻的左右翻章浮标（半透明，hover 变实）+ 键盘。触屏上不显示浮标 ——
那里已经有边缘手势，再加两个浮标只会遮正文。

## 内容宽度

- 外壳 `max-width: 56rem` 并居中。在 2560px 上铺满整屏不可读：一行字太多，眼睛
  要横扫整个屏幕。
- 正文 `max-width: 44em`（**em 不是 rem** —— 跟着用户设的字号走）。18px 下约
  790px，一行 40 来个汉字，中文长文的舒适区间。桌面上不因为屏幕宽就加宽。
- 书架网格 `minmax(132px, 164px)`，上界比下界大，所以窗口变窄时先压缩列宽再减列。
  不设上限的话宽屏上会变成二十列小方块。

## hover 与焦点

`@media (hover: hover) and (pointer: fine)` 才上 hover —— 触屏上 hover 会「粘住」
在最后点过的元素上。焦点环在 `pointer: fine` 下给更大的 offset（触屏上那个环是噪音）。

## 布局覆盖写在组件里，不写全局表

scoped 样式编译成 `.grid[data-v-x]`，特异性 (0,2,0)；全局的 `.grid` 是 (0,1,0)，
而**媒体查询不增加特异性**。写在全局表里会静默失效 —— 这一点踩过一次。

全局 `web.css` 只放：语义色变量、`--content-max` / `--rail-width`、指针相关的
hover 与焦点规则。
