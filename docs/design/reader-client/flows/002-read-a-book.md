# 从搜索到读上正文

```
搜索关键词
   │  GET /reader/search
   ├─ 0 结果 + sources_ok=0 ──→ 「所有源都没有响应」+ [重试]
   ├─ 0 结果 + sources_tried=0 ─→ 「候选源池还是空的」+ 说明怎么扫描
   ├─ 0 结果 ─────────────────→ 「没有找到这本书」+ 换关键词
   └─ 有结果
        │
        ▼ 点一本（带着 url_id + book_url 走 query）
     详情页
        │  GET /reader/book
        ├─ 422 此源不支持 ──→ 「打不开这本书」+ [换个源]
        ├─ 502 抓取失败 ───→ 同上 + [重试]
        └─ 成功
             │  POST /reader/toc（必须回传整个 BookInfo）
             ├─ 失败 ──→ 目录区单独显示错误 + [重试] [换个源]
             │           详情区照常显示，不整页崩
             └─ 成功 ──→ 目录可见
                  │
                  ▼ 点一章（或点「续读」）
               正文页
                  │  POST /reader/content（带 book_key → 走缓存）
                  ├─ 失败 ──→ 「读不到这一章」+ [重试] [换个源] [回详情]
                  └─ 成功 ──→ 恢复 char_offset，开始计进度
```

## 三个容易写错的点

**1. `BookInfo` 必须整体回传。** 规则会在详情页用 `@put` 存变量、在目录/正文页用
`@get` 取。中途丢掉 `variables`，带变量的源会静默读到空目录 —— 而且看着像「这本
书没有章节」，排查方向完全错。

**2. 目录失败不要整页崩。** 详情已经拿到了（封面、简介、来源都在），只是目录这
一步失败。整页报错会让用户连「这本书是什么」都看不到，也找不到换源入口。

**3. 正文请求要带 `book_key`。** 带了后端才会读写 `reader_chapter_cache` ——
这是离线能力的唯一来源。不带就是每次实时抓，飞行模式下直接读不到。
