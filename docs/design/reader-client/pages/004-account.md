# 账户相关页面

## 登录（`/web/login`）与注册（`/web/register`）

`bare` 形态：没有顶栏也没有 TabBar —— 还没有身份，底部导航点进去全是 401。

```
┌─────────────────────────────┐
│                             │
│          funread            │
│  登录后同步书架、进度和订阅  │
│                             │
│  用户名                      │
│  [                        ] │
│  口令                        │
│  [                    👁  ] │
│                             │
│  [        登录        ]      │
│                             │
│  还没有账号？用邀请码注册     │
│                             │
│         管理端登录           │
└─────────────────────────────┘
```

两处细节：

- `autocomplete` 分别给 `username` / `current-password` / `new-password`，
  让密码管理器能正确识别。
- 注册未开放时不显示注册链接，改为一句说明：「服务端需要配置
  `FUNREAD_REGISTER_CODE`」。给一个点进去必然 403 的链接毫无意义。

注册页先探 `/auth/accounts`：邀请码没配就**不渲染表单**，直接说明原因。让人填完
四个字段再被拒是最差的顺序。

还没有任何账号时注册页多一句：「这是第一个账号，之前没有账号时攒下的书架和进度
会归到它名下」—— 否则用户会担心注册把已有数据冲掉。

## 我的（`/web/account`）

```
┌─────────────────────────────┐
│ 我的                  [主题] │
├─────────────────────────────┤
│  (R)  reader                │
│       已登录                 │
├─────────────────────────────┤
│ 离线缓存      142 章  [清空] │
│ 搜索历史        7 条  [清空] │
│ 订阅源目录               ›  │
│ 采集源管理    管理端  [打开] │
├─────────────────────────────┤
│ [      退出登录      ]      │
└─────────────────────────────┘
```

「采集源管理」在这里而不在 TabBar：读者用不着它，但自托管的人既是读者也是管理员，
得有路径过去。用 `<a href="/admin/sources">` 整页跳转而不是 router 跳 —— 两端是
两个分包，整页跳正好触发另一个 chunk 的加载。

离线缓存的数字是逐本问一次 `GET /shelf/{key}/cached` 加起来的。书架通常几本到
几十本，几十个小请求比为这一个数字加一个聚合接口划算。
