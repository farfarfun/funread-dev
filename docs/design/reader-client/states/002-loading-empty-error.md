# 加载、空、错误

## 加载：骨架而不是转圈

`SkeletonList.vue`，按内容形状占位（封面块 + 三行文字），可配行数与有无封面。

为什么不用转圈：聚合搜索的 P50 就有好几秒，转圈期间页面是空的，用户无法判断
「是在加载」还是「加载完了但没有内容」。骨架同时传达了「马上会有一个列表」。

正文页例外，用 `n-spin` 加一句「正在抓取正文…」—— 正文的形状没法用骨架表达，
而「抓取」这个词能解释为什么慢。

## 空态：必须给下一步动作

| 页面 | 空态文案 | 下一步 |
| --- | --- | --- |
| 书架 | 书架还是空的 | [去找书] |
| 搜索（没命中） | 没有找到这本书 | 换个书名或作者再试试 |
| 搜索（源全挂） | 所有源都没有响应 | 不是没搜到，是源站这次都没答上来 + [重试] |
| 搜索（池子空） | 候选源池还是空的 | 说明要先跑一次 `POST /reader/scan` |
| 订阅 | 还没有订阅 | [浏览订阅源目录] [贴一个 feed 地址] |
| 订阅源目录（池子空） | 候选源池还是空的 | 说明要跑 `scan?source_type=rss` |
| 文章列表 | 这个分类下没有文章 | [刷新] |

**搜索的三种空态是分开的**，这是本节最重要的一条。同一个「没有结果」背后是三种
完全不同的处境，下一步动作也完全不同（换词 / 重试 / 去扫描）。合成一句「暂无
数据」等于把诊断责任推给用户。

## 错误：原因 + 重试 + 退路

统一用 `n-result status="error"|"warning"`，三要素齐全：

1. **标题说是什么坏了** —— 「目录加载失败」而不是「出错了」；
2. **描述带后端原文** —— 后端的 `detail` 已经是中文且可操作（「此源暂不支持：
   该规则要求 WebView 渲染」、「这是一个 HTML 页面而不是 feed 地址」），原样显示；
3. **至少两个按钮** —— 一个重试，一个退路（换源 / 回列表 / 回详情）。

### 422 和 502 要分开

后端刻意用不同状态码区分这两件事：

- **422** = 这个源永远不会工作（需要 JS 或 WebView）。界面该推「换源」。
- **502** = 源站这次抽风。界面该推「重试」。

只给「重试」会让人在一个结构性不支持的源上反复点。

### 局部错误不要整页崩

目录加载失败时，详情区照常显示。原则：**已经拿到的内容要留着**，失败的那一块
单独显示错误 —— 整页报错会连带藏掉用户可能需要的上下文和操作入口。
