# 我的订阅与订阅源目录

## 我的订阅（`/web/rss`）

```
┌─────────────────────────────┐
│ 订阅            [收藏][+]    │
├─────────────────────────────┤
│ [订阅源目录]        3 个订阅 │
├─────────────────────────────┤
│ ┌──┐ Hacker News            │
│ │图│ (feed) 已读 12 篇       │  [退订]
│ └──┘                         │
├─────────────────────────────┤
│ ┌──┐ SF漫画                  │
│ │标│ (归档源)                │  [退订]
│ └──┘ 上次刷新失败：超时       │  ← 红色，必须显示
└─────────────────────────────┘
```

两种来源用一个 `n-tag` 区分（`feed` / `归档源`），但**不分组**。对用户来说它们
就是订阅，分组只会强调一个他不关心的实现差别。

图标缺失时用标题首字占位，和书籍封面同一个处理。

**`last_error` 必须显示出来。** 抓取失败和「没有新内容」在界面上长得一样 ——
不显示的话用户只会以为这个源不更新了。

## 添加订阅（模态）

```
┌─────────────────────────────┐
│ 添加订阅                  × │
│                             │
│ feed 地址                    │
│ [https://example.com/feed.xml]│
│ 自定名称（可留空）            │
│ [留空则用 feed 自己的标题  ] │
│                             │
│ 支持 RSS 2.0 与 Atom。订阅前 │
│ 服务端会先抓一次验证，贴错地址│
│ 会当场告诉你。                │
│                [取消] [订阅] │
└─────────────────────────────┘
```

那段说明文字是必要的：用户需要知道「订阅」这个按钮会同步地去抓一次，可能要等
几秒，而且失败会给出具体原因。

## 订阅源目录（`/web/rss/sources`）

```
┌─────────────────────────────┐
│ ‹ 订阅源目录                 │
├─────────────────────────────┤
│ [🔍 搜源名            ] [搜索]│
├─────────────────────────────┤
│ 共 142 个可直接解析的源。     │
│ 归档里还有大量源需要 JS 或    │  ← 关键说明
│ 浏览器环境，当前版本不列出来  │
│ —— 列出来也点不开。           │
├─────────────────────────────┤
│ ┌──┐ SF漫画                  │
│ │图│ (动漫漫画) 12 个分类     │  [订阅]
│ └──┘                         │
├─────────────────────────────┤
│         [加载更多]           │
└─────────────────────────────┘
```

那段「共 142 个」的说明是这页最重要的文案。归档有 1,344 个源，只列出 142 个，不
解释的话这页看着像个坏了的列表。

池子为空时（还没跑过扫描）给的不是「暂无数据」，而是具体的下一步：
`POST /api/v1/reader/scan?source_type=rss`。
