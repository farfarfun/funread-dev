# 服务层与 API

## 两张表（28 个）

| 组 | 重点 |
| --- | --- |
| 标识 | `sub_id` 对同源稳定、按 `kind` 区分、缺标识抛 `ValueError` |
| **幂等订阅** | 重复订阅同一个源不变成两行，且字段按新值更新 |
| 按人隔离 | 订阅不互串、两人能订同一个源、知道 `sub_id` 也看不到别人的 |
| `payload` 防夹带 | 请求体里写 `user_id` 不算数 |
| 退订 | 只动调用者自己的那行；连带清掉文章状态（退订再订回来不该看到旧已读） |
| 抓取记账 | 失败写 `last_error`、**成功清掉上次的错误**（否则界面一直显示过期原因） |
| 文章状态 | 批量查、`None` 不动另一项、`meta` 只在建行时写一次 |
| `mark_all_read` | 建缺失行、返回实际改动数、再来一次返回 0 |
| 收藏 | 列表、按人隔离 |
| 表形状 | 两张表都带 `user_id`，主键是 `(user_id, sub_id)`，**不需要迁移** |

## 服务层（30 个）

| 组 | 重点 |
| --- | --- |
| 源目录 | 只列 `enabled` 的、带 group/icon/categories、关键词过滤、分页 |
| 订阅归档源 | 成功；**WebView 型当场拒绝且不入库**；未知源 `LookupError` |
| 订阅 feed | 自动取标题、显式标题、非 http 拒绝、**验证失败不入库** |
| 文章列表 | 两条腿各一组；分类生效；带已读状态；`limit` 生效 |
| 越权 | 别人的订阅取不到（`LookupError`） |
| 抓取记账 | 失败后 `last_error` 非空；成功后清空 |
| 正文 | 归档源走规则；feed 重抓再按链接找；文章已离开 feed 时 `LookupError` |
| 状态 | 已读、收藏、全部已读、`read_count` 出现在订阅行上 |

## API（32 个）

| 组 | 重点 |
| --- | --- |
| 源目录 | 只列可跑的；**首次扫描前为空**（真实安装的初始状态，界面要能分辨）；过滤分页 |
| 订阅 | feed / legado 各一组；幂等；**贴错地址 400 带原因**；非 http 拒绝；WebView 型订不上 |
| 入参校验 | `kind=legado` 缺 `url_id` → 422；`kind=feed` 缺地址 → 422；未知 `kind` → 422 |
| 退订 | 204；不存在 404 |
| 分类 | 归档源多分类；feed 单个伪分类 |
| 文章 | 列表、`next_url` 翻页、`limit`、未知订阅 404 |
| 失败可见 | 抓取失败 502，且订阅行的 `last_error` 被写上 |
| 正文 | 两条腿各一组；文章已离开 feed → 404 |
| 状态 | 标已读往返、取消已读、收藏存快照、`read-all`、空 keys → 422 |
| 越权写 | 拿不存在的 `sub_id` 写状态 → 404 |
| **跨账号隔离** | bob 看不到 alice 的订阅；知道 `sub_id` 也不能退订/读列表 |
| **鉴权** | 有账号后未登录 401；`FUNREAD_READER_PUBLIC=1` **不**放开 SSRF 端点 |
